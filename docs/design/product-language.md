# 产品语言与视觉方向

本文冻结 M0 的玩家可见语言和视觉工作模型。后续页面在实现前必须先用这三项校准内容与交互，而不是从组件库或卡片网格开始。

## Frontend-skill 工作模型

### 一句话视觉主张

以冷蓝灰的夜幕、薄雾与自绘金色星轨营造安静而精确的冒险作战台：有幻想旅途的余韵，也有值得信赖的本地工具秩序。

### 页面内容计划

应用是操作界面，不使用营销式首页 Hero。每个页面只保留一个主任务、一个主要视觉锚点和一个首要动作。

| 页面     | 首要任务                           | 内容顺序                                                                  | 主要动作             |
| -------- | ---------------------------------- | ------------------------------------------------------------------------- | -------------------- |
| 初次设置 | 完成可用的本地资料与智能服务设置   | 欢迎与隐私承诺 → 选择取数方式 → 导入资料 → 配置智能服务 → 完成检查        | 完成设置             |
| 角色一览 | 判断资料是否足够、是否需要更新     | 当前账号与更新时间 → 筛选/搜索 → 无卡片堆叠的角色阵列 → 资料缺口说明      | 更新角色资料         |
| 配队建议 | 针对一种挑战生成可执行方案         | 模式与目标 → 玩家干预/偏好 → 生成进度 → 模式专属结果结构 → 假设与数据说明 | 生成建议             |
| 历史记录 | 找回并比较曾经的方案               | 时间与模式筛选 → 版本/置信度摘要 → 方案详情                               | 再次查看或基于它重做 |
| 设置     | 管理资料、智能服务、存储和风险动作 | 连接状态 → 模型设置 → 数据与缓存 → 隐私与关于 → 危险操作                  | 保存当前分区设置     |

结果区必须按模式改变结构：深境螺旋展示联合的上下半；幽境危战展示三阶段与复用规则；幻想真境剧诗展示演员池、活力和路线。不能把三者都塞进同一个“四人队卡片”。

### 交互主张

动效用于交代层级与状态，保持迅速、克制，并尊重 `prefers-reduced-motion`：

1. **作战路径入场**：进入建议页时，模式标题、目标和主操作沿一条自绘星轨依次显现；总时长控制在约 450ms，减少动态时改为一次淡入。
2. **生成进度迁移**：分析步骤之间用同一枚光点沿路径移动，并以文本状态同步变化；它必须准确反映真实步骤，不能用无限循环伪装进度。
3. **方案切换定位**：上下半、三阶段或剧诗幕次切换采用短距离共享布局过渡（约 180–240ms），保留当前滚动与焦点，帮助玩家理解上下文没有丢失。

常规按钮、筛选和设置项不添加装饰性漂浮、呼吸或粒子效果。动效不得阻塞键盘操作或成为理解状态的唯一方式。

## 视觉约束

- 使用冷蓝灰表面、一种克制的金色强调和清晰排版建立层级；最多两套字体。
- 以工作区、分栏、分隔线和留白组织信息。卡片只有在“整块内容本身就是一个可操作对象”时使用，禁止仪表盘式卡片马赛克。
- 第一视觉锚点来自原创 SVG 构件、原创插画或生成的幻想背景，不来自游戏素材。
- 所有图形必须原创、生成或具备 CC0/OFL 等可用授权并记录在 `resources/credits.md`。
- **不得打包官方角色立绘、游戏 UI 切片、官方字体、音频或图标。** 可以表达幻想冒险氛围，但不能复刻官方界面。
- 文本优先说明当前对象、状态、新鲜度和下一步；如果一句话像广告口号，应改成操作语言。

## 玩家术语字典

代码、日志和开发文档可以使用技术名词；以下替换约束适用于按钮、标签、说明、错误和通知等玩家界面。禁用词不得因“更短”而直接泄漏到 UI。

| 禁止的默认 UI 词 | 推荐中文                          | 使用说明                                                                                              |
| ---------------- | --------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Enka             | UID 展示柜资料 / 展示柜资料       | 首次解释可写“通过 UID 读取公开展示柜资料”，不突出服务商名称。来源详情页可在二级信息中注明实际数据源。 |
| LLM              | 智能服务 / 智能模型               | 设置页用“智能服务设置”“模型名称”；不要要求玩家先理解模型类别缩写。                                    |
| fallback         | 已改用本地规则 / 备用方案         | 必须同时说明触发原因和能力差异，例如“智能服务暂不可用，已改用本地规则，建议会更保守”。                |
| partial          | 资料不完整 / 仅包含部分资料       | 紧跟缺少什么、会影响什么和可执行的补全动作。                                                          |
| stage            | 阶段 / 幕 / 步骤                  | 按语境选择：幽境危战用“阶段”，剧诗用“幕”，流程进度用“步骤”。                                          |
| slug             | 标识 / 链接标识                   | 一般不展示；确需用户编辑时写“链接标识”并给出格式示例。                                                |
| BYOK             | 使用自己的密钥 / 由你提供服务密钥 | 首次出现写清“密钥只保存在这台设备上”；不把缩写当功能名。                                              |

### 约定用语

- `spiral-abyss` → 深境螺旋
- `stygian-onslaught` → 幽境危战
- `imaginarium-theater` → 幻想真境剧诗
- `confidence` → 建议把握：较低 / 中等 / 较高
- `warnings` → 需要留意
- `assumptions` → 本次建议基于
- `stale` → 资料可能已过期
- `last-known-good` → 最近一次已确认资料
- `dataVersion` → 资料版本
- `crossPartyReusePolicy` → 跨队角色复用规则

## 状态与错误文案

状态文案采用“发生了什么 → 对结果的影响 → 玩家现在能做什么”的顺序。

- 好：`角色资料更新时间较早；本次建议可能忽略最近的配装变化。现在更新，或继续使用现有资料。`
- 好：`智能服务暂时无法连接；已改用本地规则，建议会更保守。你可以稍后重试连接。`
- 避免：`Enka partial / fallback active`。

不要承诺“必过”“最优”或“零风险”。随机路线、旧资料和缺失字段必须在方案旁就近说明，不能只藏在设置页或日志里。

## 破坏性操作文案

清除 Cookie、密钥、角色资料、历史记录或全部本地数据时，遵守以下规则：

1. 按钮直接写明对象和动作，如“清除推荐历史”“退出米游社登录”，不用含糊的“确定”“重置”。
2. 确认标题写结果，如“清除全部推荐历史？”；正文列出会删除什么、不会删除什么，以及能否恢复。
3. 不可恢复时明确写“此操作无法撤销”。可重新同步的资料写清恢复路径，不能笼统声称“可恢复”。
4. 主按钮沿用完整动作名；取消按钮写“保留并返回”。危险动作不预选、不设为回车默认项。
5. 多账号或多资料目标必须显示玩家可识别的 UID/昵称和数量，禁止只显示内部标识。
6. 涉及密钥和登录状态时不回显敏感值，只显示“已保存/未设置”和影响范围。

推荐模板：

> **清除全部推荐历史？** 这会从本机删除 24 条建议记录，不会删除角色资料或智能服务设置。此操作无法撤销。
>
> 操作：`清除 24 条历史记录`　`保留并返回`
