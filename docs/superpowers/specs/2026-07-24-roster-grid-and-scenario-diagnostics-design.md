# 角色总览响应式布局与挑战资料诊断设计

## 目标

本轮调整解决五个已经确认的问题：

1. 角色卡不再对元素充能效率输出没有证据的泛化建议，只展示面板数值。
2. 角色列表由固定两列改为随可用宽度变化的响应式网格。
3. 挑战资料不可用时展示真实原因与维护者下一步，不再只显示模糊的离线提示。
4. 每张角色卡直接展示已有完整资料，不再要求逐卡展开。
5. 搜索工具栏、角色网格以及角色卡之间保留清晰间距。

## 已确认的根因

### 角色卡

- `CharacterCard` 用本地 `expanded` 状态控制详细面板，导致同一行中展开卡与未展开卡高度和信息密度相差过大。
- `.gta-character-list` 固定为两列，并在 `1180px` 以下强制单列，没有根据实际卡片可读宽度自动分配列数。
- 工具栏与角色网格之间没有外部间距；现有 `gap` 只控制卡片之间的距离。
- `roster.energyPanel.known` 在数值后附加“是否够用需结合角色、队伍产球与实战循环判断”，没有为玩家提供额外决策信息。

### 挑战资料

`resources/scenario-production.json` 当前明确设置为：

```json
{
  "version": 1,
  "enabled": false
}
```

因此三个正式玩法服务都会返回 `production-source-not-configured`。这不是玩家账号、米游社连接或智能服务配置错误。

仓库内现有旧版场景 JSON 已经过期，且不属于当前配队工作台消费的签名 `ScenarioV2` 发布链；开发样例是虚构演练资料，也不能作为本期正式推荐依据。

完整生产功能仍依赖独立数据链：

1. 采集并审核深境螺旋、幻想真境剧诗和幽境危战当前正式服资料。
2. 转换为 strict `ScenarioV2` publication。
3. 使用受控 Ed25519 私钥签名。
4. 通过 HTTPS 发布 manifest、payload 与 integrity 文件。
5. 将 manifest URL 和对应公钥写入 App 的生产配置。

## 交互与布局设计

### 角色卡内容

- 移除展开按钮、`aria-expanded` 状态和条件渲染。
- 所有卡片始终展示：
  - 头像、等级、命座、元素和星级；
  - 当前武器、可参与反应和元素充能效率；
  - 完整面板属性；
  - 武器、天赋和圣遗物摘要；
  - 已取得的圣遗物详情与资料来源。
- 已知元素充能效率只显示格式化后的百分比，例如 `119.9%`。
- 未知数值继续显示“暂无可靠面板数据”，不伪造 `0%`。

### 响应式网格

角色网格使用内容驱动的 CSS Grid：

```css
grid-template-columns: repeat(auto-fit, minmax(min(100%, 540px), 1fr));
```

预期结果：

- 窄窗口：1 列；
- 常规桌面窗口：2 列；
- 约 2K 宽屏：3 列；
- 更宽屏：在每张卡仍不少于约 `540px` 时自然增加到 4 列。

不再保留 `1180px` 以下强制单列的规则。`540px` 下限保证卡内属性和装备双栏仍能正常阅读。

### 间距

- 工具栏与角色网格之间增加 `16px` 上间距。
- 角色卡行列间距统一为 `16px`。
- 卡片仍使用现有淡元素色背景和切角边框，不增加新的装饰层。

## 挑战资料不可用状态

新增纯展示映射，根据场景服务返回的 `reason` 给出精确说明：

| 原因 | 玩家标题 | 说明与下一步 |
| --- | --- | --- |
| `production-source-not-configured` | 正式挑战资料源尚未接入 | 明确这是应用维护侧尚未接入签名数据源，不要求玩家修改账号或模型设置 |
| `production-config-invalid` | 正式挑战资料配置无效 | 提示维护者检查 Manifest 地址与 Ed25519 公钥配置 |
| `production-data-unavailable` | 正式挑战资料更新失败 | 提示已配置数据源，但下载、校验或读取未得到可用版本 |
| `development-sample-invalid` | 演练资料校验失败 | 说明仅影响开发演练资料 |

三个挑战工作台复用同一个原因映射组件或展示函数，并保留各玩法服务返回的补充消息。生产数据链未建立前，推荐按钮继续保持不可用，避免把过期或虚构数据冒充本期事实。

## 测试设计

### 单元测试

- 角色卡源码测试断言：
  - 不再含 `expanded` 状态和展开按钮；
  - 详细面板无条件渲染；
  - 已知充能文案只包含百分比。
- 布局测试断言：
  - 网格使用 `auto-fit` 与 `540px` 最小宽度；
  - 不再存在 `1180px` 下强制单列；
  - 工具栏与网格、卡片之间具有 `16px` 间距。
- 挑战资料状态测试覆盖四种不可用原因的中文和英文映射。

### Electron E2E 与视觉回归

- 角色卡无需点击即可看见完整属性、天赋、圣遗物和来源。
- 页面中不再出现充能泛化建议或角色卡展开按钮。
- 在 `1024×768`、`1280×800`、`1440×900`、`1600×1000` 视口运行视觉矩阵，验证列数、间距、溢出和文字可读性。
- 更新受角色页布局影响的视觉签名。

## 不在本轮伪装完成的范围

- 不把旧版或开发样例场景数据改名为“本期资料”。
- 不在 App 仓库内存放生产签名私钥。
- 不在没有来源审核和签名发布的情况下直接启用 `scenario-production.json`。
- 不把独立生产数据仓库和持续更新任务伪装为一次前端修复。
