# 1.0 冲刺开发计划

> 计划日期：2026-07-15
> 仓库基线：`master` / `bde84fa`
> 输入文档：`docs/handoff-miyoushe-profile-to-llm.md`
> 建议周期：3 个工作日预冲刺 + 5 个双周 Sprint，共约 10.5 周

> **执行更新（2026-07-16）**：Sprint 1～4 的实现与本机自动门禁已完成，版本已进入 `1.0.0-rc.1`。当前 No-Go 只剩必须依赖外部状态或目标平台的验收：真实米游社账号矩阵、Anthropic/兼容 Provider、Apple 公证、GitHub draft Release/rc 更新、Windows CI/NSIS 结果与 5 天 RC soak。实时证据见 `docs/rc-validation.md`。

## 1. 执行结论

1.0 不应直接进入“签名发版”阶段。当前最短关键路径是：

```text
真实登录态 gate
  -> 米游社 list/detail + 风控降级
  -> Profile v2（unknown / provenance / coverage）
  -> LLM serializer + 多 Agent 编排
  -> E2E / 安全 / 双平台打包
  -> 签名、自动更新、RC 验证
```

推荐按 **2 名全职工程师 + 兼职 QA/设计支持**排期，每个双周 Sprint 只承诺 16 个工程人日，预留约 20% 容量处理外部接口、SDK 和打包问题。若由 1 名工程师独立完成，日历时间应按 **18～22 周**估算，不建议通过取消真实账号 gate、E2E 或 RC soak 压缩。

1.0 的发布判断只有两个：

- **Release**：核心数据链路、LLM 输入、多 Agent、安全、安装更新五类门禁全部通过。
- **No-Go**：任一 P0 门禁未通过即继续 RC，不以“Enka 展示柜可用”或“本地开发环境能运行”替代。

## 2. 本轮继续调研得到的新结论

### 2.1 米游社与 Enka

- 活跃维护的 `genshin.py` 仍使用 `POST character/list` 取得 owned IDs，再使用 `POST character/detail` 取得完整详情，交接文档的技术方向成立。[调用实现](https://github.com/seriaati/genshin.py/blob/master/genshin/client/components/chronicle/genshin.py#L78-L125)
- 国际服 Genshin Battle Chronicle 当前 route 是 `https://sg-public-api.hoyolab.com/event/game_record/genshin/api`；仓库中的 `bbs-api-os.hoyolab.com/game_record/genshin/api` 已落后。[当前 routes](https://github.com/seriaati/genshin.py/blob/master/genshin/client/routes.py#L141-L154)
- Enka 明确要求自定义 User-Agent，并对 UID endpoint 实施动态限流；重复请求即使命中缓存仍计入限流，客户端必须尊重响应 `ttl`。缺失 `avatarInfoList` 表示展示柜关闭或为空，不等于玩家没有角色。[Enka API](https://github.com/EnkaNetwork/API-docs/blob/master/api.md#before-you-request)

### 2.2 Agent SDK

- 仓库声明 `^0.1.10`，lockfile 当前安装 `@anthropic-ai/claude-agent-sdk@0.1.77`；2026-07-15 npm latest 为 `0.3.210`，不能把现状视为稳定的生产集成。
- 当前代码把 `Task` 放入 `disallowedTools`，而新版 SDK 文档把 sub-agent 工具称为 `Agent`，`Task` 仅作为兼容别名。升级时必须同时审计 `Agent`、`Task`、后台任务和权限 hook，避免意外暴露原生工具。
- 新版 SDK 默认从平台可选依赖解析原生 Claude Code binary；当前仓库显式指向包内 `cli.js` 的方案需要用 macOS/Windows 打包产物重新验证，不能只靠 tsup/build 成功判断。[TypeScript SDK 参考](https://code.claude.com/docs/en/agent-sdk/typescript)
- 当前 `permissionMode: 'bypassPermissions'` 不适合作为 1.0 默认值。建议改为精确 `allowedTools` + `dontAsk`，并用 `PreToolUse` 默认拒绝未登记工具；Orchestrator 只额外获得受限的 `Agent` 能力，所有子 Agent 禁止递归 spawn。

### 2.3 Electron 与发布

- 本地安装 Electron `39.8.10`，npm latest 为 `43.1.1`。Electron 官方只维护最新三个稳定大版本，39 已不应作为 1.0 发布基线。[Electron 支持策略](https://www.electronjs.org/docs/latest/tutorial/electron-timelines)
- `electron-builder.json` 显式只构建 macOS DMG。`electron-updater` 的 macOS 更新需要签名，并需要 ZIP 目标生成 `latest-mac.yml`；当前配置不能完成自动更新。[自动更新要求](https://www.electron.build/auto-update.html)
- 生产依赖审计发现 `undici@7.25.0` 有 1 个 high 等级漏洞，`7.28.0` 有可用修复。该项必须在进入 beta 前清零。[GitHub Advisory](https://github.com/advisories/GHSA-vmh5-mc38-953g)

## 4. 1.0 范围锁定

### 4.1 Must Have

- 米游社完整 owned roster + 当前装备 build snapshot；partial 必须可见、可解释。
- Enka 作为展示角色精确补强和无登录预览，不承担全角色池职责。
- Profile v2：optional unknown、field provenance、per-character completeness、profile coverage、旧缓存迁移。
- 紧凑、稳定、可测试的 Advisor serializer；fallback 不再把 unknown 当 0。
- Orchestrator、DataCurator、TeamComposer、Critique、RotationCoach、Explain 六类职责按契约落地；1.0 采用 1 个 host control plane + 5 个隔离 LLM roles，不开放递归 Agent/Task。
- API Key/Cookie 不进入 Renderer，日志和 fixture 不包含 secret、完整 UID 或 raw profile。
- Roster 显示数据完整度；Advisor 显示置信度、假设和降级原因。
- zh-CN / en-US UI；中文推荐为默认，英文至少覆盖完整应用 UI、错误与发布文档。
- macOS 签名、公证、自动更新；Windows NSIS 可安装、可卸载、可更新，Windows 1.0 暂不签名。
- CI、单测、契约测试、Electron E2E、packaged smoke、外部 opt-in gate。

### 4.2 明确不进入 1.0

- 读取未装备背包中的全部武器和圣遗物。
- SaaS 后端、账号系统、云同步、遥测。
- OpenAI-compatible provider 抽象；仍保持 Anthropic Messages 协议 + 可配置 base URL。
- Linux Release。
- Windows 代码签名。
- `sessions.sqlite`、无限历史、云端全文检索。
- 游戏内立绘、官方 UI 切片、官方字体。

## 5. 冲刺安排

### Sprint 0：风险闸门与工程地基（3 个工作日）

目标：在承诺完整实现前，把三个最可能推翻计划的未知数变成事实。

| 任务                                   |   工作量 | 负责人建议 | 验收                                                                  |
| -------------------------------------- | -------: | ---------- | --------------------------------------------------------------------- |
| S0-01 ESLint flat config + CI skeleton | 1.0 人日 | B          | lint/typecheck/unit/build 在 PR 上运行                                |
| S0-02 `undici` 安全升级                | 0.5 人日 | A          | `npm audit --omit=dev` 无 high/critical                               |
| S0-03 脱敏 `gate:miyoushe-detail`      | 2.0 人日 | A          | 同一登录态跑 index/list/detail，输出 coverage summary                 |
| S0-04 SDK 0.3.x 兼容与打包 spike       | 1.5 人日 | B          | macOS packaged app 成功 query；确认 binary、权限和 tool exposure      |
| S0-05 Release 凭据与渠道清单           | 0.5 人日 | B/维护者   | Apple Developer ID、Team ID、GitHub Release 权限有明确 owner          |
| S0-06 Architecture Decision Record     | 0.5 人日 | A+B        | 锁定 SDK 版本、Electron 版本、Agent 权限模型和 GitHub update provider |

Go/No-Go：

- **GO-A**：direct list/detail 成功，进入 direct-first 实现。
- **GO-B**：direct 触发 captcha，但官方页面能返回 list/detail，进入 bridge-first 实现。
- **GO-C**：两者都失败，仍可开发 Profile/serializer/Enka/发布工程，但不得承诺“1.0 完整 build”；需增加 1 周风险缓冲并招募 3～5 个不同账号/IP 做 beta gate。
- SDK 打包 smoke 失败时，不进入多 Agent 开发；先完成 SDK adapter 与平台 binary 方案。

### Sprint 1：角色数据主链路（第 1～2 周）

目标：把“登录成功”升级为“全角色详情有统计、失败有分类”。

#### Main / Data

- S1-01 将 `/index` 改为 ping + expected count，不再命名为 details。
- S1-02 增加 CN/global endpoint builder，global 改为当前 `sg-public-api` route。
- S1-03 实现 `postSigned<T>()`，签名与发送复用同一 body 字符串。
- S1-04 实现 list/detail schema、mapper、分批、顺序保持、重复/缺失 ID 检测。
- S1-05 BrowserBridge 同时观察 list/detail；visible 验证后重试目标也改为 list/detail。
- S1-06 统一 auth-expired、captcha-required、rate-limited、signature、network、schema-drift 分类；区分正 `5003` 与负 `-5003`。
- S1-07 日志默认关闭 verbose；body 只记录 endpoint/count/hash/length。
- S1-08 Enka 解析 weapon、equip/reliquary、skillLevelMap、talentIdList；实现 `ttl` 本地节流和 429 backoff。

#### Test / Gate

- 脱敏真实 schema fixture；不得包含 UID、昵称、Cookie 或原始面板值。
- POST DS 固定向量；list/detail mapper；batch/partial/order；所有错误分类。
- external gate 默认不进 CI，无持久登录态时明确 skip。

Sprint 验收：

- `index.expectedOwnedCount === list.count`，不一致时返回 partial，不静默成功。
- detail 返回的每个 ID 都能追溯到 list；所有遗漏都有 coverage 记录。
- 真实账号能取得 weapon/relic/skill/property 中至少三类字段，或稳定进入 typed bridge/partial 降级。
- 日志搜索不到 Cookie key 的值、完整 UID 和 raw response。

### Sprint 2：Profile v2 与 LLM 数据边界（第 3～4 周）

目标：让应用和 LLM 对“知道什么、不知道什么”达成一致。

#### Domain / Storage

- S2-01 引入 `CharacterBuildSnapshot`、`FieldProvenance`、`DataCompleteness`、`ProfileCoverage`。
- S2-02 `stats` 和各 stats field 改为 optional；删除全 0 placeholder。
- S2-03 明确 field-level merge：ownership、build、stats 分开选源，冲突规则有单测。
- S2-04 ProfileStore 增加 `schemaVersion: 2` 和 v1 容错迁移；迁移失败保留原文件并提示重新拉取。
- S2-05 Roster 增加“详细 / build / 基础 / 已过期”标签、missing fields 和 coverage 摘要。

#### Advisor Boundary

- S2-06 新建纯函数 `advisor-profile-serializer.ts`。
- S2-07 传入 level、constellation、talents、weapon、artifact sets、三件关键主词条、核心 stats、completeness/missingFields。
- S2-08 禁止 icon、描述、全部 substats、raw response 进入 prompt；同一输入必须稳定序列化。
- S2-09 Prompt 明确 unknown 不是 0、不能推断未培养、数据敏感结论必须带假设。
- S2-10 fallback 改为基础元数据 + 已知 build 的可解释排序；unknown 只降低置信度，不直接降为最弱。

Sprint 验收：

- 任意旧 cache 都不会制造假 0；新 cache 可读取、重启后保持 coverage。
- 100 角色 fixture 的 serializer 输出不超过 48 KiB，且没有描述文本、URL、substats。
- Advisor 请求 fixture 中可见 weapon/talents/artifactSummary/completeness。
- partial profile 的 UI、prompt、fallback 使用同一 missing 语义。

### Sprint 3：多 Agent 推荐与质量评估（第 5～6 周）

目标：完成仓库定义的“group team”核心，而不是继续扩张单一 Advisor prompt。

#### SDK 与权限

- S3-01 建立 `AgentSdkAdapter`，隔离 query options、binary path、usage、cancel、错误分类。
- S3-02 精确 pin 经 spike 验证的 SDK 版本，不保留宽泛 caret。
- S3-03 Main 内 host Orchestrator 只执行版本化 route policy；五个 LLM roles 禁止 `Agent/Task/Bash/Read/Write/Edit/Web*`。多轮对话若需原生 `Agent` 必须另立 ADR。
- S3-04 使用 `dontAsk` + default-deny `PreToolUse`，移除生产默认 `bypassPermissions`。

#### Agent Contract

- S3-05 每个 Agent 独立目录、版本化 prompt、Zod 输入输出契约和最大时限。
- S3-06 DataCurator 输出 ProfileBundle，不进入对话历史。
- S3-07 TeamComposer 只输出 2～3 套结构化队伍；Critique 强制执行且不修改队伍。
- S3-08 RotationCoach 按需生成每套循环；Explain 只转写已验证产物。
- S3-09 Host Orchestrator 只路由、校验、取消和汇总，不直接生成队伍。
- S3-10 usage event 写入本地月度计数，Settings 显示估算用量，不上传遥测。

#### Eval

- 建立至少 30 个脱敏离线 case：全量、partial、无 Enka、元素免疫、充能不足、少于 4 人、双环境。
- 所有 LLM 输出先 Zod parse，再做 known-ID、4 人、重复角色、生存位等确定性校验。
- 任一子 Agent 超时/错误可终止并进入本地 fallback，不留下半条历史。

Sprint 验收：

- schema parse 成功率 100%（mock/eval fixture），未知角色 ID 为 0。
- Critique 对每套 Composer 输出恰好执行一次。
- partial case 不生成依赖未知武器/套装的确定性结论。
- 取消操作能停止当前完整编排；同一时间不串 UID/side/correlationId。
- packaged macOS smoke 能完成真实或 mock provider 的完整编排。

### Sprint 4：Release 工程、i18n 与安全（第 7～8 周）

目标：从“能跑”升级为“社区用户能安装、升级、排障”。

#### Platform / CI

- S4-01 升级到 Sprint 0 锁定的受支持 Electron 大版本；当前建议验证 43.x，而不是继续发布 39.x。
- S4-02 GitHub Actions：macOS/Windows 执行 lint、typecheck、unit、renderer E2E、build。
- S4-03 tag Release：目标 OS 原生构建，避免跨平台漏装 SDK optional binary。
- S4-04 macOS `dmg + zip`、Developer ID 签名、公证、`spctl` 验证。
- S4-05 Windows NSIS 安装/覆盖升级/卸载 smoke；保留不签名提示文档。
- S4-06 `electron-updater` 使用 GitHub Releases；实现 available/progress/downloaded/error UI 与手动检查。

#### Product Hardening

- S4-07 建立 i18n 层，迁移所有 renderer、IPC error、更新提示到 zh-CN/en-US。
- S4-08 安全复核：CSP、navigation deny、IPC whitelist、secret redaction、safeStorage、partition logout、MCP allowlist。
- S4-09 `resources/credits.md`、隐私说明、数据获取、LLM provider、故障排查、许可证说明补齐。
- S4-10 精简字体构建产物；定义首屏、安装包大小和冷启动基线，记录而不盲目重构 UI。

Sprint 验收：

- CI 绿色且 `npm audit --omit=dev` 无 high/critical。
- macOS 签名公证产物可在干净机器启动；Windows NSIS 可安装和卸载。
- 从 `1.0.0-rc.1` 自动更新到 `rc.2` 成功，缓存/Profile/API Key 保持不丢。
- 中英文切换无需重启，所有核心流程无硬编码中文漏项。

### Sprint 5：RC、Beta 与 1.0 发布（第 9～10 周）

目标：只修 blocker/critical，不再增加功能。

#### Beta 矩阵

- macOS：Apple Silicon + Intel（至少打包和启动验证）；当前/上一个受支持系统版本。
- Windows：Windows 11；若继续声称支持 Windows 10，必须有一台真实或云机验证。
- 米游社：至少 3 个国服账号/不同角色数量；可用条件下增加 1 个国际服 HoYoLAB 账号。
- 数据源：展示柜开启/关闭、Enka 429、米游社 captcha、Cookie 过期、partial detail。
- LLM：Anthropic 直连 + 至少 1 个兼容 base URL；错误 key、超时、限额、非标准错误体。
- 更新：新装、覆盖安装、rc.1 -> rc.2、离线检查、下载中退出重进。

#### RC 规则

- RC 开始后只接受 P0/P1、数据丢失、安全、崩溃、无法安装/更新修复。
- 每次 RC 修复都必须增加回归测试或明确的 manual gate。
- 最后一个 RC 至少稳定 5 个自然日；期间出现 P0 则重新计时。
- 发布前更新 `package.json`、README、CHANGELOG、隐私/credits、下载与校验说明。

## 8. 任务并行与依赖

建议两个开发泳道：

- **A：Main/Data** — external gate、米游社/Enka、Profile、存储迁移、安全日志。
- **B：Agent/Renderer/Release** — serializer、Agent SDK、UI、i18n、E2E、CI/打包。

硬依赖：

```text
S0 external gate -> S1 acquisition -> S2 Profile v2 -> S3 Agent eval -> S5 beta
S0 SDK spike --------------------------> S3 Agent SDK -> S4 target-OS pack -> S5 update
S0 CI skeleton -> S1/S2 tests -> S4 release workflow -> S5 RC
S0 credentials --------------------------> S4 notarization -> S5 release
```

S4 的 CI/i18n 可以在 S1～S3 提前铺设，但不得抢占 P0 数据链路容量。

## 9. 每个 PR 的 Definition of Done

- 需求有对应 typed contract 或 schema，不以 `unknown as` 绕过边界。
- 新行为有 unit/contract test；用户流程变化有 E2E 或 manual gate。
- 错误可分类、可提示、可恢复；禁止 silent partial success。
- 日志经过 secret/UID/profile redaction review。
- Renderer 不新增外部 fetch；Preload 不新增非白名单 channel。
- `npm run lint && npm run typecheck && npm run test && npm run build` 通过。
- 影响打包/SDK/更新的变更必须跑 packaged smoke。
- 文档、CHANGELOG、prompt version 与代码同步。

## 10. 第一周可直接开工的顺序

1. 修 ESLint flat config、`undici` 漏洞并建立 CI skeleton。
2. 实现 main-process-only 脱敏 detail gate，使用真实登录态跑请求矩阵。
3. 保存 sanitized schema fixture，确认 direct/bridge 选择。
4. 建立 SDK adapter spike，验证新版 SDK、`Agent`/`Task` 权限和 macOS packaged binary。
5. 确认 Apple Developer ID、GitHub Release 权限和 1.0 目标系统版本。
6. 开 Sprint 1：endpoint、POST signer、mapper、coverage、错误分类按这个顺序合并。

这六项完成前，不建议同时开 Profile 大迁移、多 Agent prompt 调优或自动更新 UI；这些任务依赖的数据和 SDK 契约尚未稳定，提前展开会产生返工。
